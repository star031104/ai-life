## 微信版 2.5.0 — 能放 Linux 服务器（Windows 版不变）
- **Linux 版微信**（4.x，跑在 Docker 里，网页 VNC 扫码）：config.yaml 写了 `wechat.container`（或 `wechat.linux: true`）就走 Linux 方式，
  不写就和以前的 Windows 版一模一样。新文件 `aigroup/wechat/linux.py`：
  - 拿库密钥：`/proc/<pid>/maps` + `/proc/<pid>/mem` 只读微信内存（同样的 HMAC 校验、同样的深度扫描兜底）
  - 认哪个进程开着她的库：`/proc/<pid>/fd`，按“账号目录/db_storage/…”比，容器里外路径不一样也认得出
  - 发消息：`xdotool` + `xclip`（通过 `docker exec` 在容器的显示里）切到群的单独窗口 → 粘贴 → 回车，发完照旧去库里核对
  - 发图片：先存到微信看得到的目录（`wechat.outbox`），`wechat.path_map` 把宿主机路径换成微信看到的路径
- 部署脚本 `scripts/linux/`（Dockerfile、`wechat_up.sh`、systemd 服务），步骤写在 [docs/LINUX.md](docs/LINUX.md)；加了 `install.sh`、`start.sh`
- 人设：她现在住在服务器上、24 小时在线（`persona/local_*.md` 自己改）；示例人设 `xiaoman.md` 加了“群聊节奏”（看清是谁在跟谁说、
  不每条都接、被叫到一定回）、冷场 / 吵架 / 让她换角色这几段示例
- 测试：新加 `tests/test_linux.py`（读自己进程的内存、认窗口、xdotool 发送顺序、路径换算、按账号尾巴认文件）

## 微信版 2.2.1
实测发现：电脑上同时开着你的大号和她的小号时，配置向导会认成大号（挑的是最近改动过的账号）。
- **认出哪个微信登录着哪个号**：用 Windows 的 Restart Manager 看谁开着这个号的库文件（和“文件被占用”提示同一个接口），
  再按父子进程分出“这是哪个微信”（keys.owner_pids / instances）
- **配置向导**：开着好几个微信时，列出每个号的昵称让你选哪个是她的小号；没选的号（你的大号）读过的密钥、解密副本都删掉；
  只开着一个微信就直接用它；开着的另一个号也在选的群里，就先当成是你
- **发消息只用她那个微信的窗口**：大号也开着同一个群的窗口不会被用上；她的号没登录就不发；
  认不出哪个是她、又找到两个同名窗口时拒发；两个主窗口又认不出时不用搜索方式
- 她的号的微信关了（大号还开着）也算“微信没在运行”；拿密钥先找她那个微信的进程
- wxdiag 显示每个账号登录在哪个进程、她用的是哪个微信
- 选好号以后，以前读过的别的号的密钥、解密副本都删掉（比如上次选成了大号）
- 测试 127 个

## 微信版 2.1.0
复查 + 调研之后修的：
- **绝不发错群**：默认不再用“Ctrl+F 搜群名”的方式（打开的到底是哪个会话核对不了），只认群的单独窗口；
  前台判断改成只认那一个窗口（主窗口在前台不算）；群没有名字、和别的会话同名时不发（同名可以在 window_titles 写明窗口标题）；
  打开搜索方式的话，只要一次没核对上就停用
- **绝不抢键盘**：等你停手最多等 60 秒，你还在用就这次不发（以前等够了照发）
- **剪贴板原样还原**：图片、复制的文件也放回去（以前只还原文字）
- **不丢消息**：一轮里中途出错，水位线不往前走，下一轮整批重读；读通讯录出错不连累消息
- **补消息按 id 去重**：先实时收到新的、后补到更早的也能补进去（以前按时间比会漏）；补几次都不重复
- **确认晚到**：她发的话超过 confirm_seconds 才在库里出现，也会记成她说的（不再丢）；确认不再比电脑时钟
- **服务器 id**：刚发出去还没有服务器 id 时等几秒，群友引用她这句时认得出是在回她
- **拿密钥不卡收消息**：新分片缺密钥时另开线程去找，找不到 5 分钟、10 分钟……越隔越久再试
- **口令派生兜底**：x'…' 当裸密钥验不过时，再按“口令 → PBKDF2-SHA512 256000 次”派生一遍试（有文章说 4.1 存的是口令）
- **解密副本每个进程一份**：体检、wxtail 和正在跑的她互不覆盖；退出的进程留下的副本自动清掉
- 大库分块读（每次 256 页），不再整个读进内存；临时图片发没发出去都删掉；配置了账号就只认它，不悄悄换号；
  拍一拍认 fromusername
- 修了一个测试在晚上 23 点跑会失败的问题（心情的基线跟钟点走）
- 测试 115 个，ruff 全过

## 微信版 2.0.0（群聊大脑 = QQ 群版 3.3.0）
- **大脑整体升级到 QQ 群版 3.3**：群梗词条、持续心情、按群友节奏回、画像更细（口头禅 / 群里关系 / 怎么聊、带日期、每天仔细回想）、群友别名、AI 腔检测器和“帮她挑一句”、扣分制评审、质检误伤统计（calibrate）、DeepSeek 关思考 + JSON 模式、提示词按缓存排；代码分层（core / llm / chat / memory / web / eval）、命令注册表、设置集中
- **从本地库补消息**：接上微信时（程序重启、电脑关机、微信没开之后）直接从微信的本地库补上群里说过的话（每个群最多 200 条），期间 @ 她的补一句“才看到”；她的号在手机上说的话记成“她说的”
- **成员和群名片**：接上时从通讯录库拉一遍群成员和群名片（没说过话的人也知道叫什么）；config 里的 `people_aliases` 照样能用
- **微信关了又开**：每 30 秒看一眼微信还在不在，关了先不说话，开回来自动接上并补消息；读库连续出错就从头再接一次
- **离线消息不乱接**：微信刚开时同步下来的旧消息（比 `stale_seconds` 旧）不当成刚说的话一条条接，交给补消息
- **发送更稳**：两条之间至少隔 `send_gap_seconds`，每小时最多 `max_sends_per_hour` 条；时钟差几分钟也认得出自己刚发的那条
- **微信小表情**：小黄脸换成 [捂脸] [旺柴] 这种写法发出去；她自己写的 [破涕为笑] 也保留（粘进去就是表情）
- **不让她选做不到的事**：提示词里不给“点表情”这个选项（微信点不了）；模型还是选了就改成说话或者不说
- 小屋顶上显示微信状态：接没接上 / 微信没在运行、哪个群没开单独窗口、这小时发了多少条、没拿到密钥的库；托盘加了“微信接入体检”
- 配置向导：旁边装了 QQ 群版就问要不要直接用它配好的大模型接口（程序本身仍不预置任何接口）
- 测试 106 个（新增 test_wechat_v2.py）；ruff 全过
